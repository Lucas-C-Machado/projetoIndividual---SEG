Slide 07 — Um atributo também pode ser um objeto 🟦 CONCEITO

Até agora usamos bastante tipos primitivos:

private string $nome;
private float $valor;
private int $quantidade;

Mas podemos ter um tipo de classe:

private Plano $plano;

private string $plano;

Guarda uma simples string com o nome do plano.

private Plano $plano;

Referencia uma instância inteira do OBJETO Plano.

Slide 08 — Criando Plano 🟦 CONCEITO 
class Plano
{
    private string $nome;
    private float $valorMensal;

    public function __construct(
        string $nome,
        float $valorMensal
    ) {
        $this->nome = $nome;
        $this->valorMensal = $valorMensal;
    }

    public function getNome(): string
    {
        return $this->nome;
    }

    public function getValorMensal(): float
    {
        return $this->valorMensal;
    }
}

Temos agora uma classe responsável pelos dados e comportamentos do PLANO.

Slide 09 — Agora Aluno conhece Plano 🟦 CONCEITO 
class Aluno
{
    private string $nome;
    private string $matricula;
    private Plano $plano; // Atributo é um Objeto!

    public function __construct(
        string $nome,
        string $matricula,
        Plano $plano
    ) {
        $this->nome = $nome;
        $this->matricula = $matricula;
        $this->plano = $plano;
    }
}

Observe o parâmetro: Plano $plano

O objeto Aluno agora mantém uma referência direta para um objeto Plano. Temos um RELACIONAMENTO ENTRE OBJETOS.

Slide 10 — Como instanciamos? 🟦 CONCEITO

Primeiro criamos o plano:

$planoPremium = new Plano(
    "Premium",
    129.90
);

Depois injetamos a instância no construtor do aluno:

$aluno1 = new Aluno(
    "Lucas",
    "2026001",
    $planoPremium
);

Observe o terceiro argumento: $planoPremium

Não estamos passando a string "Premium". Estamos passando UM OBJETO completo.

Slide 11 — Visualizando 🟦 CONCEITO
$planoPremium │ ↓ ┌──────────────┐ │ PLANO │ │ Premium │ │ R$ 129,90 │ └──────▲───────┘ │ │ referencia │ ┌──────┴───────┐ │ ALUNO │ │ Lucas │ │ 2026001 │ └──────────────┘
Esse é um salto importante na POO:
Um objeto pode colaborar com outros objetos para representar uma solução.
Slide 12 — Damos um nome a essa ideia: Associação 🟦 CONCEITO

Quando objetos possuem algum tipo de vínculo ou interação, representamos um RELACIONAMENTO.

A forma mais geral de relacionamento é a ASSOCIAÇÃO.

Exemplos Clássicos:

  • Professor ───── Aluno
  • Cliente ───── Pedido
  • Aluno ───── Curso
  • Médico ───── Paciente

Conceito:

A associação indica que objetos se conhecem ou colaboram de alguma maneira durante a execução do sistema.

Slide 13 — Pense antes de classificar 🟦 CONCEITO

PROFESSOR ───────── ALUNO

Um professor pode acompanhar um aluno.

Pergunta:
Se o Professor deixar de existir no sistema, o Aluno necessariamente precisa deixar de existir?

Resposta: Não. E se o Aluno sair? O Professor também não deixa de existir.

Temos objetos que podem existir INDEPENDENTEMENTE.

Slide 14 — Associação em PHP 🟦 CONCEITO

Uma possibilidade de associação simples por método:

class Professor
{
    private string $nome;

    public function acompanharAluno(Aluno $aluno): void
    {
        echo "Acompanhando o aluno " . $aluno->getNome();
    }
}

Observe: Aluno $aluno passado como argumento.

A ideia importante neste momento não é memorizar a sintaxe, mas perceber: Existe uma colaboração entre objetos.

Slide 15 — Agora outra situação: Agregação 🟦 CONCEITO

Imagine: EQUIPE E PROFESSOR

Uma equipe pode possuir vários professores:

EQUIPE / | \ / | \ ↓ ↓ ↓ Prof Prof Prof
Mas pergunte:
Se a equipe for desfeita, os professores deixam de existir?

Não necessariamente. Eles possuem existência própria fora da equipe.

Slide 16 — Agregação 🟦 CONCEITO

Quando temos uma relação de todo e parte, mas a parte pode existir independentemente do todo, modelamos uma AGREGAÇÃO.

TODO ↓ possui ↓ PARTE (mas a PARTE possui existência independente)

Exemplo: Equipe → Professor

A equipe agrega professores. A equipe é o TODO; os professores são as PARTES independentes.

Slide 17 — Outro exemplo de Agregação 🟦 CONCEITO
BIBLIOTECA ↓ LIVROS
Se uma biblioteca fechar ou deixar de existir... os livros precisam obrigatoriamente ser destruídos ou deixar de existir?

Não! Eles podem ser transferidos, vendidos, doados ou pertencer a outra biblioteca.

Essa existência independente da PARTE caracteriza a AGREGAÇÃO.

Slide 18 — Agora mude a situação: Composição 🟦 CONCEITO

Imagine um PEDIDO composto por ITENS DO PEDIDO:

Pedido #1058 │ ├── Item: Mouse × 2 ├── Item: Teclado × 1 └── Item: Monitor × 1
Pergunta:
O que significa "Item do Pedido #1058" se o próprio Pedido #1058 nunca existiu ou for destruído?

Aqui a relação é bem diferente.

Slide 19 — Composição 🟦 CONCEITO

Na COMPOSIÇÃO também existe uma relação TODO → PARTE.

Porém, existe uma dependência forte de ciclo de vida entre a parte e o todo.

PEDIDO (Todo) ↓ ITEM DO PEDIDO (Parte dependente)

O ItemPedido só existe como parte integrante daquele Pedido específico. Se o Pedido deixar de existir, os Itens perdem o sentido.

Slide 20 — Não decore apenas palavras 🟦 CONCEITO
Relação Ideia Central
Associação Objetos se relacionam / colaboram
Agregação Relação Todo/Parte com maior independência da Parte
Composição Relação Todo/Parte com forte dependência de ciclo de vida
Atenção:
Não memorize "Professor + Escola = Agregação". A pergunta correta é:
O que esse relacionamento significa NESTE sistema específico?
Slide 21 — O contexto importa 🟦 CONCEITO

Carro ─── Motor

Alguém pode imediatamente dizer: "Composição!"

Mas precisamos entender as regras do negócio:

  • O sistema é de uma oficina que troca e vende motores usados separadamente? (Agregação)
  • O sistema apenas calcula impostos de veículos sem gerenciar motores isolados? (Composição)

O relacionamento é uma DECISÃO DE MODELAGEM, não apenas uma propriedade física do mundo real.

Slide 22 — Classifique e justifique NOVA AÇÃO

Para cada situação, discutam em duplas qual relacionamento faz mais sentido:

Slide 25 — Adicionando objetos em arrays IMPLEMENTAÇÃO 
class Equipe
{
    // ...
    public function adicionarProfessor(Professor $professor): void
    {
        $this->professores[] = $professor;
    }
}

Observe a tipagem: Professor $professor

Estamos recebendo um OBJETO EXTERNO e armazenando sua referência dentro do array $this->professores[].

Slide 26 — Utilizando a Agregação IMPLEMENTAÇÃO 
$prof1 = new Professor("Ana");
$prof2 = new Professor("Carlos");

$equipe = new Equipe("Equipe A");

$equipe->adicionarProfessor($prof1);
$equipe->adicionarProfessor($prof2);
Quem foi criado primeiro?
Os professores foram criados fora. Se $equipe for destruída, $prof1 e $prof2 continuam existindo no programa.
Slide 27 — Desafio prático: Sistema de Pedidos DESAFIO PRÁTICO

Modelem em PHP as classes PEDIDO e ITEMPEDIDO:

Pedido

numero, cliente, itens (array)

ItemPedido

produto, quantidade, valorUnitario

O pedido deve conseguir possuir VÁRIOS ITENS.

PRIMEIRO: MODELEM NO PAPEL. Depois programem.

Slide 28 — Requisitos da Solução DESAFIO PRÁTICO

Sua estrutura de arquivos deve conter:

  • Pedido.php
  • ItemPedido.php
  • index.php

Passos obrigatórios:

  1. Criar classes, atributos privados, construtores e getters.
  2. No index.php, criar 1 pedido e adicionar pelo menos 3 itens nele.
  3. Exibir a lista de itens e calcular o valor total do pedido.
