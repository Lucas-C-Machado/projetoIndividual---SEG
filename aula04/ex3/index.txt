1. Cliente / Pessoa

Faz sentido? SIM!   
Um Cliente é uma Pessoa? SIM!
Justificação: Cliente é uma especialização de Pessoa. Todo cliente possui dados
básicos de uma pessoa (nome, CPF, endereço), acrescentando apenas informações de
compras ou cadastro de cliente.

2. Pedido / Cliente

Faz sentido? NÃO!   
Um Pedido é um Cliente? NÃO!   
Justificação: Trata-se de uma relação de
Associação/Composição ("tem um"), e não de herança ("é um"). Um Pedido pertence
a ou tem um Cliente, mas não é um tipo de cliente.

3. Carro / Veiculo

Faz sentido? SIM!   
Um Carro é um Veiculo? SIM!   
Justificação: Carro é uma especialização de
Veiculo. Herda características gerais (marca, modelo, ano) e adiciona
especificidades de um automóvel.

4. Motor / Veiculo

Faz sentido? NÃO!   
Um Motor é um Veiculo? NÃO!   
Justificação: Trata-se de uma relação de Composição/Agregação
("tem um"). O Veículo tem um Motor, mas o Motor isoladamente não é um veículo.

5. Professor / Funcionario

Faz sentido? SIM!   
Um Professor é um Funcionario? SIM!
Justificação: Professor é um tipo específico de Funcionario. Herda dados
genéricos da empresa/escola (matrícula, salário, CPF) e possui atribuições
próprias da docência (disciplinas, turmas).

6. Livro / Biblioteca

Faz sentido? NÃO!   
Um Livro é uma Biblioteca? NÃO!   
Justificação: Trata-se de uma relação de Agregação ("tem um" / "contém"). 
A Biblioteca contém vários Livros, mas um Livro não é uma biblioteca.

7. PagamentoPix / Pagamento

Faz sentido? SIM!   
Um PagamentoPix é um Pagamento? SIM!   
Justificação: PagamentoPix é uma forma/tipo específico de Pagamento. 
Herda os atributos gerais de transação financeira (valor, data, status) 
e adiciona a lógica e chave do Pix.
